## AI学习助手

**分类:** 学习工具

**难度:** 进阶

**时长:** 3-5 天

**目标:** 帮助用户把学习目标拆成每日任务、资料摘要、实操练习和复盘问题。

**业务价值:** 适合企业内训、个人技能成长和团队知识沉淀，让学习从收藏资料变成稳定输出成果物。

**实现步骤:**

- 定义学习计划、每日任务、资料摘要和成果物的数据模型。
- 实现学习控制台：今日目标、任务列表、进度、复盘入口。
- 加入 Prompt 复制和学习记录收藏功能。
- 增加 7 天或 30 天计划视图，并支持按标签筛选。

**Prompt:**

请用 Next.js、TypeScript、TailwindCSS 实现一个中文 AI 学习助手。数据从本地 JSON 读取，首页是学习控制台，包含今日任务、学习进度、资料摘要、实操任务和复盘问题。约束：不接后端，支持深色模式和移动端。DoD：搜索、标签筛选、收藏、复制 Prompt 可用。


**优化建议:**

- 把学习内容和 UI 解耦，后续可接入数据库。
- 复盘问题要指向成果物，不要停留在感受。
- 进度展示要反映真实完成项，而不是装饰性百分比。

**成果物:**

- 学习控制台
- 每日计划数据
- Prompt 复制功能
- 复盘模板

**交付检查清单:**

### 学习数据模型可扩展

**acceptance:** 至少包含学习目标、每日任务、理论摘要、实操任务、成果物、复盘问题和标签字段。

**evidence:** 提交 data/daily-plan.json 或同等数据文件，并能新增一天内容而不修改组件结构。

### 控制台能指导今日行动

**acceptance:** 首屏能看到今日任务、完成状态、下一步行动和复盘入口。

**evidence:** 提供桌面与移动端截图，用户不阅读说明也能开始当天任务。

### 进度状态真实可操作

**acceptance:** 支持标记完成、取消完成、重置进度，并在刷新后保留状态。

**evidence:** 浏览器 localStorage 或等效本地状态中能看到完成记录。

### Prompt 可直接复制使用

**acceptance:** 每个学习任务至少有一条可复制 Prompt，包含目标、上下文、约束和交付标准。

**evidence:** 复制后粘贴到 Codex 能生成明确任务，不需要用户二次组织需求。

### 学习闭环包含复盘

**acceptance:** 每个阶段都能生成复盘问题或复盘报告，指向下一次改进动作。

**evidence:** 完成一天任务后能输出一份包含问题、证据、改进项的 Markdown 复盘。


**标签:**

- 学习
- 控制台
- Prompt
- 复盘

## AI知识库

**分类:** 知识管理

**难度:** 进阶

**时长:** 4-7 天

**目标:** 把文章、模板、Prompt、案例沉淀成可搜索、可筛选、可复制的团队知识库。

**业务价值:** 降低新人上手成本，减少重复问答，让团队经验从个人文档变成组织资产。

**实现步骤:**

- 设计 Article、Template、Prompt、Case 四类内容模型。
- 实现统一搜索与分类筛选。
- 做详情页，展示适用场景、步骤、示例和注意事项。
- 增加收藏和最近访问，提升高频内容使用效率。

**Prompt:**

请构建一个中文 AI 知识库网站。内容来自 data/*.json，支持文章、模板、Prompt 和案例四种资源。实现搜索、分类、标签、收藏、复制按钮和响应式布局。UI 风格参考 Apple、OpenAI、Linear，黑白灰为主，少量蓝紫渐变。


**优化建议:**

- 详情页要强调可执行步骤和示例。
- 标签体系不要过多，优先匹配工作流。
- 内容更新机制比一次性页面更重要。

**成果物:**

- 知识库首页
- 资源列表
- 详情组件
- 收藏系统

**交付检查清单:**

### 知识内容结构统一

**acceptance:** 文章、模板、Prompt、案例都具备标题、场景、正文、标签、适用对象和更新说明。

**evidence:** 新增任意资源后，列表、搜索、详情页都能自动渲染。

### 搜索与筛选能定位资源

**acceptance:** 支持关键词、分类和标签组合筛选，空结果有明确提示。

**evidence:** 用 3 个典型关键词测试，能在 2 次点击内找到目标内容。

### 详情页强调可执行动作

**acceptance:** 详情页不仅展示解释，还包含步骤、示例、注意事项和复制入口。

**evidence:** 用户复制内容后可以直接用于会议、项目或 Codex 任务。

### 高频资源可快速回访

**acceptance:** 支持收藏或最近访问，刷新页面后状态保留。

**evidence:** 收藏 2 条内容后返回首页或列表页能再次看到入口。

### 内容维护有边界

**acceptance:** 说明数据源、更新流程、命名规则和废弃内容处理方式。

**evidence:** README 或内容维护文档中包含新增、修改、删除知识条目的流程。


**标签:**

- 知识库
- 搜索
- 标签
- 团队

## AI售前助手

**分类:** 安全售前

**难度:** 高阶

**时长:** 5-8 天

**目标:** 根据客户行业、需求、现状和产品能力，生成客户拜访 Brief、方案大纲和跟进邮件。

**业务价值:** 帮助安全售前提升会前准备质量，缩短方案初稿时间，减少遗漏客户真实痛点。

**实现步骤:**

- 定义客户画像、拜访目标、痛点、产品能力和输出模板。
- 实现客户信息输入表单和场景选择。
- 输出拜访 Brief、探查问题、方案大纲和邮件草稿。
- 加入案例库和常见风险提示。

**Prompt:**

请实现一个面向中国安全行业的 AI 售前助手。场景包括零信任、SASE、数据安全、XDR、MSS。输入客户行业、现状、痛点、参会角色和我方能力，输出客户拜访 Brief、问题清单、方案大纲和跟进邮件。约束：不编造客户信息，不承诺产品不存在能力。


**优化建议:**

- 问题清单按业务、技术、采购、交付分层。
- 输出要区分事实、假设和建议。
- 方案要先讲客户现状，再讲产品能力。

**成果物:**

- 客户输入表单
- 拜访 Brief
- 方案大纲
- 跟进邮件模板

**交付检查清单:**

### 输入区分事实与假设

**acceptance:** 客户行业、现状、痛点、参会角色、已知限制和待验证信息必须分区录入。

**evidence:** 输出结果中能看到事实、推断、待确认三类标记。

### 拜访 Brief 可直接会前使用

**acceptance:** Brief 包含客户背景、目标、关键问题、风险、建议议程和会后动作。

**evidence:** 复制到企业微信或邮件后格式仍清晰，不需要大量手工整理。

### 探查问题按角色分层

**acceptance:** 问题覆盖业务负责人、IT、安全、采购和交付角色，避免只问技术功能。

**evidence:** 至少输出 12 个问题，并标注每个问题的提问目的。

### 方案大纲绑定客户痛点

**acceptance:** 每个能力模块都对应一个客户痛点、价值说明和验证证据。

**evidence:** 方案中不出现与输入痛点无关的产品堆砌段落。

### 不承诺不存在能力

**acceptance:** 未知产品能力、客户信息和交付边界必须标注待确认。

**evidence:** 输出中包含风险边界或待确认列表，避免编造客户事实。


**标签:**

- 售前
- 安全
- 客户拜访
- 方案

## 客户画像助手

**分类:** 销售效率

**难度:** 进阶

**时长:** 3-5 天

**目标:** 把客户公开资料、访谈记录和项目线索整理成结构化画像。

**业务价值:** 让销售、售前和交付团队对客户现状、决策链、痛点和机会形成统一认知。

**实现步骤:**

- 设计客户基本信息、组织架构、业务目标、痛点、决策链和风险字段。
- 实现资料录入和结构化输出。
- 生成客户机会判断和下一步行动。
- 加入画像质量检查：缺失字段、假设和待验证问题。

**Prompt:** 请开发一个客户画像助手。输入客户行业、公开资料、会议记录和已知需求，输出客户画像：业务背景、组织角色、关键痛点、现有系统、决策链、预算信号、风险、下一步行动。要求标注事实、推断和待验证信息。

**优化建议:**

- 画像不是百科，要服务下一步销售动作。
- 把未知字段显式列出来。
- 为每个判断保留来源或依据。

**成果物:**

- 画像模板
- 结构化输出
- 待验证问题
- 行动建议

**交付检查清单:**

### 画像结论有来源

**acceptance:** 客户背景、组织角色、痛点和机会判断都要标注来源或依据。

**evidence:** 任意一条关键判断都能回溯到公开资料、会议记录或用户输入。

### 未知信息显式暴露

**acceptance:** 预算、决策链、现有系统、时间节点等未知字段不能自动补全。

**evidence:** 输出中有待验证问题清单，并按优先级排序。

### 画像服务下一步动作

**acceptance:** 每份画像都输出下一次拜访目标、推荐提问和推进动作。

**evidence:** 销售或售前能根据画像安排下一场沟通，而不是只阅读客户百科。

### 机会与风险同时呈现

**acceptance:** 输出包含机会信号、阻力因素、竞争风险和信息缺口。

**evidence:** 至少列出 3 个风险或不确定项，并给出验证方式。

### 画像可复制到业务文档

**acceptance:** 支持复制 Markdown 或结构化文本，适合进入 CRM、飞书或项目文档。

**evidence:** 复制后格式包含标题层级和字段标签，不依赖网页样式。


**标签:**

- 客户画像
- 销售
- 结构化
- 机会

## 竞品分析助手

**分类:** 市场与售前

**难度:** 进阶

**时长:** 4-6 天

**目标:** 围绕具体客户场景比较竞品，而不是只生成通用功能表。

**业务价值:** 支持销售攻防、方案差异化和产品策略复盘，提升面对竞品时的回应质量。

**实现步骤:**

- 定义竞品、客户场景、对比维度和证据来源。
- 实现功能、部署、成本、服务、生态、风险等维度对比。
- 生成我方差异化打法和需要验证的问题。
- 输出销售问答和方案替换段落。

**Prompt:** 请构建一个竞品分析助手。输入我方产品、竞品资料、客户场景和关注点，输出定位对比、能力对比、客户价值对比、竞品风险、我方差异化打法、销售攻防话术和验证清单。未知信息必须标注，不允许编造。

**优化建议:**

- 竞品分析必须绑定客户场景。
- 避免用功能数量代表价值。
- 输出销售可用的问答，而不只是表格。

**成果物:**

- 竞品对比表
- 差异化打法
- 攻防话术
- 验证清单

**交付检查清单:**

### 竞品分析绑定客户场景

**acceptance:** 每次分析必须输入客户行业、业务目标、现有环境、关注指标和竞品名称。

**evidence:** 输出的对比维度能解释为什么与当前客户有关。

### 关键判断有证据等级

**acceptance:** 把官网资料、公开案例、客户反馈、内部经验和推断分开标注。

**evidence:** 每个高风险结论后都有证据类型或待验证标记。

### 对比不止功能列表

**acceptance:** 至少覆盖部署复杂度、成本、运维、服务、生态、风险和客户价值。

**evidence:** 表格之外输出我方差异化打法和客户沟通重点。

### 销售攻防话术可直接使用

**acceptance:** 输出常见质疑、推荐回应、禁用说法和需要回避的夸大承诺。

**evidence:** 至少包含 5 组问答，并符合中国企业客户沟通语气。

### 验证清单指导下一步调研

**acceptance:** 输出需要向客户、产品、交付或渠道确认的问题清单。

**evidence:** 清单按优先级排列，并说明不确认会影响哪个判断。


**标签:**

- 竞品
- 销售攻防
- 市场
- 售前

## 会议纪要助手

**分类:** 办公自动化

**难度:** 入门

**时长:** 2-3 天

**目标:** 把会议记录自动整理为结论、行动项、风险和待确认问题。

**业务价值:** 减少会议后整理成本，提升行动项跟进质量，避免信息遗失。

**实现步骤:**

- 定义会议输入和纪要输出模板。
- 实现原始记录粘贴和结构化预览。
- 生成行动项表格，包含负责人、截止时间、状态。
- 支持复制 Markdown 和保存收藏。

**Prompt:** 请实现一个中文会议纪要助手。输入原始会议记录，输出会议主题、背景、关键结论、行动项、风险和待确认问题。未明确负责人或截止时间时标记待确认。支持一键复制 Markdown。

**优化建议:**

- 行动项必须结构化。
- 不确定信息不要自动补全。
- 复制格式要适合企业微信、飞书或邮件。

**成果物:**

- 会议输入区
- 纪要预览
- 行动项表格
- 复制按钮

**交付检查清单:**

### 原始记录输入足够宽容

**acceptance:** 支持粘贴口语化记录、转写文本、项目群聊天或简短要点。

**evidence:** 不同格式输入都能生成结构化纪要，而不是要求用户先整理。

### 纪要结构覆盖结论和行动

**acceptance:** 输出会议背景、关键结论、行动项、风险、待确认问题和下次会议建议。

**evidence:** 复制出的 Markdown 有稳定标题层级和行动项表格。

### 行动项不编造负责人

**acceptance:** 负责人、截止日期或状态不明确时标注待确认。

**evidence:** 测试一段缺少负责人的记录，输出中不能自动虚构姓名。

### 复制格式适合办公工具

**acceptance:** 复制内容在企业微信、飞书、邮件中可读，表格不散乱。

**evidence:** 粘贴到至少一个办公场景后仍保留标题和列表结构。

### 会后跟进能复盘

**acceptance:** 纪要底部包含待确认信息和下次跟进问题。

**evidence:** 用户能根据纪要直接发起下一轮沟通或创建任务。


**标签:**

- 会议纪要
- Markdown
- 行动项
- 办公

## 方案生成助手

**分类:** 安全售前

**难度:** 高阶

**时长:** 6-10 天

**目标:** 根据客户痛点和产品能力生成售前方案大纲、价值说明和实施路径。

**业务价值:** 缩短方案初稿周期，提高方案与客户痛点的匹配度，并统一团队方案结构。

**实现步骤:**

- 定义客户现状、建设目标、能力模块、实施阶段和价值指标。
- 实现方案结构生成和章节编辑。
- 加入风险边界和交付假设。
- 输出 Markdown 或可复制的汇报大纲。

**Prompt:** 请开发一个安全售前方案生成助手。输入客户行业、现状、痛点、我方产品能力和交付边界，输出客户现状、建设目标、总体架构、能力清单、实施路径、价值评估、风险边界和下一步计划。内容要专业、克制、适合中国企业正式汇报。

**优化建议:**

- 方案从客户问题开始，不从产品功能开始。
- 每个能力模块都要对应痛点。
- 价值评估要尽量关联效率、风险、合规或成本。

**成果物:**

- 方案生成页
- 章节模板
- 风险边界
- 复制导出

**交付检查清单:**

### 方案从客户问题开始

**acceptance:** 输出先描述客户现状、痛点和建设目标，再展开产品能力。

**evidence:** 首屏或首段不以我方功能清单开头。

### 章节结构适合正式汇报

**acceptance:** 包含现状分析、建设目标、总体架构、能力模块、实施路径、价值评估和风险边界。

**evidence:** 复制到 PPT 或 Word 后可直接作为售前方案大纲。

### 能力模块与痛点一一映射

**acceptance:** 每个能力说明都包含对应痛点、业务价值、落地条件和验证指标。

**evidence:** 抽查任意模块，能找到明确客户问题来源。

### 交付边界和假设清晰

**acceptance:** 对客户未确认信息、产品限制、第三方依赖和交付前提进行标注。

**evidence:** 输出中包含风险边界章节，避免过度承诺。

### 方案可复制导出

**acceptance:** 支持复制 Markdown 或汇报大纲，格式适合继续交给 Codex 生成页面或 PPT。

**evidence:** 复制内容包含标题层级、列表和下一步行动。


**标签:**

- 方案
- 售前
- 安全
- 价值

## Agent助手

**分类:** Agent开发

**难度:** 高阶

**时长:** 7-12 天

**目标:** 帮助用户设计、拆解、实现和评估一个小型 Agent。

**业务价值:** 降低团队从 Prompt 到 Agent 的落地门槛，避免盲目构建万能 Agent。

**实现步骤:**

- 设计 Agent Canvas：任务、输入、输出、工具、记忆、边界、评估。
- 实现 Agent 需求分析和工作流判断。
- 生成 Codex 实现 Prompt 和测试样例。
- 加入评估清单和失败模式复盘。

**Prompt:**

请实现一个 Agent 设计助手。输入业务场景和用户任务，输出是否需要 Agent、Agent Canvas、输入输出 schema、工具清单、状态和记忆、失败模式、评估样例以及 Codex 实现 Prompt。约束：不要把普通流程强行包装成 Agent。


**优化建议:**

- 先问是否需要 Agent。
- 输出 schema 决定后续工程质量。
- 评估样例必须包含失败场景。

**成果物:**

- Agent Canvas
- 实现 Prompt
- 评估样例
- 失败模式清单

**交付检查清单:**

### 先判断是否需要 Agent

**acceptance:** 输出必须说明该场景是否需要 Agent，还是普通工作流或一次性 Prompt 更合适。

**evidence:** 至少列出需要 Agent 的原因和不需要 Agent 的替代方案。

### Agent Canvas 信息完整

**acceptance:** 包含任务、输入、输出、工具、状态、记忆、边界、失败模式和评估指标。

**evidence:** Canvas 可以直接转化为 Codex 实现任务。

### 输入输出 schema 明确

**acceptance:** 关键输入、输出和中间状态都有字段定义、类型和示例。

**evidence:** 开发者能基于 schema 编写类型或接口，不需要猜字段。

### 评估样例覆盖成功和失败

**acceptance:** 至少包含正常任务、边界任务、缺失信息、工具失败和错误恢复样例。

**evidence:** 运行评估样例后能判断 Agent 是否达到可用标准。

### Codex 实现 Prompt 可执行

**acceptance:** Prompt 包含目标、仓库上下文、约束、实现步骤、测试方式和 Definition of Done。

**evidence:** 复制给 Codex 后能直接开始实现，而不是继续追问基础信息。
